Все агентские системы можно разделить на:
* **Workflows** - системы, где LLM и инструменты оркестрируются через заранее определенные пути в коде;
* **Агенты** - системы, где LLM динамически управляют своими процессами и использованием инструментов, сохраняя контроль над выполнением задач.
## Усиленная LLM

Главная часть любой агентской системы - LLM, дополненная такими вещами, как инструменты, поиск и память.

![[Pasted image 20260925151936.png]]

Необходимо учитывать два аспекта реализации: адаптацию под конкретный сценарий использования и обеспечении удобного и хорошо задокументированного интерфейса для LLM.

### Workflow: Цепочка запросов

Цепочка запросов декомпозирует задачу в последовательность шагов, где каждый вызов LLM обрабатывает вызов предыдущего. Можно добавить программные проверки (Gate) на любых промежуточных шагах, чтобы убедиться, что процесс идет корректно.
![[Pasted image 20260925162607.png]]

**Когда стоит использовать:** Этот workflow идеальный для ситуаций, где задача может быть легко и чисто декомпозирована в фиксированные подзадачи. Главная цель - компенсировать задержку ради большей точности, делая каждый вызов LLM проще.
**Примеры использований:** 
- Создание маркетингового текста, а затем его перевод на другие языки;
- Написание плана документа, проверка его соответствия определенным критериям, а затем написание документа на основе этого плана.
### Workflow: Маршрутизация

Маршрутизация классифицирует вход и направляет его к специализированной последующей задаче. Этот workflow позволяет разделять вопросы и создавать более специализированные запросы. Без такого workflow оптимизация под каждый тип входов может снизить производительность других входов.
![[Pasted image 20260925163704.png]]

**Когда стоит использовать:** Маршрутизация хорошо работает для сложных задач, где существуют отдельные категории, которые лучше решать отдельно, и где классификация может быть точно обработана либо с помощью LLM, либо с помощью традиционной модели классификации/алгоритма.
**Примеры использований:**
* Направление разных типов запросов обслуживания клиентов в разные процессы, запросы и инструменты;
* Маршрутизация простых/распространённых запросов к более компактным, экономичным моделям, а сложные/необычные вопросы - к более мощным моделям.

### Workflow: Параллелизация 

LLM иногда могут одновременно выполнять задачу и иметь программные агрегированные выводы. Этот workflow, параллелизация, проявляется в двух ключевых вариациях:
* *Секционирование:* Разбиение задачи на независимые подзадачи, выполняемые параллельно;
* *Голосование:* выполнение одной задачи несколько раз, чтобы получить разнообразные результаты.
![[Pasted image 20260925164914.png]]

**Когда использовать:** Параллелизация эффективна, когда разделенные подзадачи можно параллелизовать для достижения скорости, или когда для достижения более уверенных результатов требуется несколько точек зрения или попыток. Для сложных задач с множеством факторов LLM обычно работают лучше, когда каждое соображение обрабатывается отдельным вызовом LLM, что позволяет сосредоточиться на каждом конкретном этапе.

**Примеры использования:** 
* **Секционирование:**
	* Внедрение ограничительных механизмов, при которых один экземпляр модели обрабатывает пользовательские запросы, а другой проверяет их на наличие неподходящего контента или запросов. Это обычно работает лучше, когда один и тот же LLM вызов обрабатывает как ограничители, так и основной ответ;
	* Автоматизация оценок для оценки производительности LLM, где каждый вызов LLM оценивает разные аспекты производительности модели по заданному запросу.
* **Голосование:**
	* Обзор куска кода на уязвимости, когда несколько разных запросов проверяют и отмечают код при обнаружении проблемы;
	* Оценка того, является ли определенный контент неуместным, с множеством подсказок, оценивающие разные аспекты, или требуя разных порогов голосования для баланса ложных и отрицательных результатов.

### Workflow: Оркестратор-работники

В workflow оркестратора-работников, центральная LLM динамически разделяет задачу, делегирует подзадачи к LLM работникам и синтезирует их результаты.

![[Pasted image 20260925170428.png]]

**Когда использовать:** Этот workflow подходит для сложных задач, где не получается предсказать необходимые подзадачи. Хотя топографически она схожа, главное отличие параллелизации - её гибкость - подзадачи не заранее определены, а определяются оркестратором на основе конкретного входа.

**Примеры:**
* Продукты для программирования, которые вносят сложные изменения в несколько файлов каждый раз.
* Задачи поиска, которые включают сбор и анализ информации из нескольких источников для возможного актуальной информации.

### Workflow: Оценщик-оптимизатор

В workflow оценщик-оптимизатор, один вызов LLM генерирует ответ, а другой обеспечивает оценку и обратную связь в цикле.

![[Pasted image 20260925171121.png]]

**Когда использовать:** Этот workflow, в частности, эффективно, когда имеем понятный критерий оценки, и когда итеративная доработка дает измеримую ценность. Два признака хорошего подхода заключается в том, что ответы LLM могут быть заметны улучшены, когда человек выражает свою обратную связь. Это аналогично итеративному процессу написания, через который может пройти человек-писатель при создании отшлифованного документа.

**Примеры:**
* Литературный перевод, где есть нюансы, которые LLM-переводчик может изначально не зафиксировать, но когда LLM-оценщик может предоставить полезную критику;
* Задача комплексного поиска, который требует несколько раундов поиска и анализа для сбора полной информации, при этом оценщик решает, необходимы ли дальнейшие поиски.

### Агенты

Агенты начинают работу либо с команды, либо с интерактивного обсуждения с человеком. Когда задача ясна, агенты планируют и действуют независимо, потенциально возвращаясь к человеку для получения дополнительной информации или суждений. Во время выполнения крайне важно, чтобы агенты получали "правдивость" от окружения на каждом этапе, чтобы оценить его прогресс. Агенты могут делать паузу для обратной связи человека на контрольных точках или при встрече с блокаторами. Задача часто завершается после завершения выполнения, но также часто включают условия остановки для сохранения контроля.

Агенты могут обработать утонченной задачи, но их реализация часто проста. Обычно это просто LLM, использующие инструменты, основанные на обратной связи по окружающей среде в цикле. Поэтому крайне важно четко и продуманно разрабатывать наборы инструментов и их документацию.

![[Pasted image 20260925173835.png]]

**Когда использовать:** Агенты могут быть использованы для открытых задач, где сложно или невозможно предсказать необходимое количество шагов, и где невозможно жестко закодировать фиксированный путь. LLM потенциально будет работать много ходов, и вы должны доверять её решениям. Автономия агентов делает их идеальными для масштабирования задач в надежных средах. 

Природа автономности агентов означает высокие затраты и возможность усугубления ошибок. Рекомендуется провести обширные испытания в песочницах с соответствующими ограничениями.

### Комбинирование

Эти паттерны не являются конечными. Это распространенные паттерны, которые разработчики могут использовать и комбинировать под различные сценарии. Но сложность стоит добавлять только тогда, когда явно улучшается результат.

### Принципы построения агента

При реализации агентов необходимо следовать этим трем принципам:
1. Сохранение простоты дизайна;
2. Прозрачность каждого шага;
3. Разработка интерфейса агента с тестированием и документацией.
