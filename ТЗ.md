# ТЕХНИЧЕСКОЕ ЗАДАНИЕ

**Тема:** «Сравнительное исследование методов дообучения больших языковых моделей для автономного решения задач программной инженерии»

## 1. Назначение разработки

### 1.1. Функциональное назначение

Разработка предназначена для исследования и повышения эффективности автономного программного агента на основе большой языковой модели Gemma 4 при решении задач программной инженерии.

В рамках работы предусматривается исследование методов обучения с учителем (Supervised Fine-Tuning, SFT), параметрически эффективной адаптации (Low-Rank Adaptation, LoRA) и обучения с подкреплением (Reinforcement Learning, RL).

Целью разработки является **повышение доли успешно решённых задач программной инженерии по сравнению с исходной моделью Gemma 4** посредством применения и сравнительного исследования методов дообучения.

### 1.2. Эксплуатационное назначение

Результаты разработки предназначены для использования в составе автономного программного агента, функционирующего в предоставленной инструментальной среде.

Агент применяется для анализа программных репозиториев, локализации ошибок, модификации исходного кода, запуска автоматизированных проверок и формирования программных патчей.

Разработка собственного агентного фреймворка, среды исполнения инструментальных вызовов и системы инференса языковой модели в состав работы не входит.

## 2. Требования к программе или программному изделию

### 2.1. Требования к функциональным характеристикам

Программное решение должно обеспечивать:

1. Обработку текстовых описаний задач программной инженерии.
    
2. Многошаговое взаимодействие языковой модели с программным репозиторием посредством предоставленных инструментов.
    
3. Формирование корректных инструментальных вызовов и обработку результатов их выполнения.
    
4. Анализ исходного кода, локализацию ошибок, внесение изменений и проверку исправлений.
    
5. Формирование итогового программного патча в установленном формате.
    
6. Подготовку обучающих данных, содержащих последовательности действий агента и результаты взаимодействия с окружением.
    
7. Дообучение Gemma 4 с использованием SFT и параметрически эффективной адаптации LoRA.
    
8. Проведение экспериментов по обучению с подкреплением с использованием автоматически проверяемого вознаграждения.
    
9. Загрузку и использование полученных адаптеров в совместимой среде исполнения.
    
10. Сбор экспериментальных данных, необходимых для расчёта технико-экономических показателей.
    
11. Сравнительную оценку исходной и адаптированных моделей на едином наборе тестовых задач.

### 2.2. Требования к надёжности (переименовать)

Должны предусматриваться:

1. Проверка корректности конфигурационных файлов и параметров модели.
    
2. Обработка ошибок инструментальных вызовов, недопустимых аргументов и некорректных изменений исходного кода.
    
3. Сохранение промежуточных результатов обучения и контрольных точек модели.
    
4. Регистрация параметров и результатов экспериментальных запусков.
    
5. Воспроизводимость экспериментов при фиксированных настройках и контролируемых условиях тестирования.
    
6. Корректное завершение выполнения задач при достижении установленных ограничений времени и ресурсов.


### 2.3. Условия эксплуатации

Адаптированная модель должна функционировать в программной среде, совместимой с архитектурой Gemma 4 и предоставленным инструментальным окружением программного агента.

Для проведения экспериментов допускается использование локальных и удалённых вычислительных ресурсов.

### 2.4. Требования к составу и параметрам технических средств

Для проведения дообучения предусматривается использование графических ускорителей, поддерживающих применяемые методы машинного обучения.

Необходимый объём оперативной и видеопамяти определяется выбранной конфигурацией Gemma 4, длиной обучающих последовательностей, параметрами LoRA и алгоритмом обучения с подкреплением.

### 2.5. Требования к информационной и программной совместимости

Должна обеспечиваться:

1. Совместимость конфигурации агента с предусмотренным конкурсной средой форматом Google ADK.
    
2. Совместимость обучающих данных с форматом диалогов, инструментальных вызовов и результатов выполнения инструментов.
    
3. Совместимость полученных адаптеров с базовой моделью Gemma 4 и средой инференса.
    
4. Возможность сохранения результатов экспериментов в машиночитаемом формате.
    
5. Разделение обучающих, валидационных и тестовых данных для исключения утечек информации.
    

## 3. Технико-экономические показатели

Для оценки эффективности разработки устанавливаются четыре технико-экономических показателя.

### 3.1. Доля успешно решённых задач

Показатель характеризует результативность автономного программного агента и определяется отношением количества успешно решённых задач к общему количеству задач тестовой выборки:

$$
SR=\frac{N_{\mathrm{solved}}}{N_{\mathrm{total}}}\cdot 100%  
$$

где:

- $N_{\mathrm{solved}}$ — количество успешно решённых задач;
    
- $N_{\mathrm{total}}$ — общее количество задач тестовой выборки.
    

Для определения изменения результативности применяется показатель:

$$  
\Delta SR=SR_{\mathrm{trained}}-SR_{\mathrm{baseline}}  
$$

где:

- $SR_{\mathrm{trained}}$ — доля успешно решённых задач после дообучения;
    
- $SR_{\mathrm{baseline}}$ — доля успешно решённых задач исходной моделью.
    

**Целевой результат:** повышение доли успешно решённых задач по сравнению с исходной моделью Gemma 4.

### 3.2. Среднее количество инструментальных вызовов

Показатель характеризует эффективность взаимодействия агента с программным окружением:

$$
\overline{C}=\frac{1}{N}\sum_{i=1}^{N}C_i  
$$

где:

- $N$ — количество тестовых задач;
    
- $C_i$ — количество инструментальных вызовов при выполнении (i)-й задачи.
    

Единица измерения: вызовов на задачу.

### 3.3. Среднее время выполнения задачи

Показатель характеризует временные затраты на решение программных задач:

$$
\overline{T}=\frac{1}{N}\sum_{i=1}^{N}T_i  
$$

где:

- $N$ — количество тестовых задач;
    
- $T_i$ — время выполнения $i$-й задачи.
    

Единица измерения: секунд на задачу.

Время выполнения включает генерацию ответов модели, инструментальные взаимодействия и проверку результата в пределах выполнения агентной задачи.

### 3.4. Вычислительные затраты на дообучение

Показатель характеризует вычислительные ресурсы, необходимые для адаптации языковой модели:

$$
G=\sum_{j=1}^{m}n_jt_j  
$$

где:

- $m$ — количество этапов обучения;
    
- $n_j$ — количество графических ускорителей на (j)-м этапе;
    
- $t_j$ — продолжительность (j)-го этапа обучения в часах.
    

Единица измерения: GPU·ч.

Показатель используется для сравнительной оценки вычислительной ресурсоёмкости исследуемых методов дообучения.

Экономическая эффективность определяется с учётом достигнутого изменения результативности и вычислительных затрат. При наличии тарифов на вычислительные ресурсы дополнительно рассчитывается стоимость обучения.
